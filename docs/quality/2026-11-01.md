# Quality check against the 10 rules (2026-11-01)

Applied from the start while building M1 (run 2026-11-09) on Windows 11 (Intel Core i7-13700H)
with Python 3.14.5 in the repo's `.venv`. Mutations were applied one at a time by a scratch
script that restored each file right after its pytest run (`.tmp/mutate.py`, not shipped).

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Assume every call can fail | pass | Every socket has a timeout (`connect`: 0 to 60 s, default 5 s) and the server thread is joined with a bound; TLS, SVID and socket errors become a recorded `deny` with the reason, never a silent pass. Envoy clusters have connect timeouts (1 s, 2 s) and route timeouts (5 s, 10 s request), no retries. Every `kubectl`/`curl` in `e2e.sh` and `register.sh` is wrapped in `timeout` or `--max-time`, and every wait loop is bounded. |
| 2 | Writes safe to retry | pass | Files are written to a sibling temp file, fsynced and renamed (`files.write_atomic`); a test checks the temp file is removed when the rename fails. `ztmesh render` only rewrites changed files and a second run changes nothing (tested). `register.sh` treats an existing entry as success; the kind job runs it twice. |
| 3 | No race conditions | pass | `connect` binds the listener before starting the server thread, so the client cannot connect early; results pass through a list read only after `join`. Each test gets its own temp directory. |
| 4 | Don't trust the clock | pass | Durations use `time.monotonic`; stored times are UTC with a `Z` suffix; `ca.py` rejects naive or non-UTC timestamps and `verify_svid` rejects naive times. SVIDs are backdated 10 s for clock skew but never before the CA. |
| 5 | Read before changing | pass | No environment variables are read by the package; the CLI documents every flag (`--help`). The scaffold's README order and CI pins were kept. |
| 6 | Never break compatibility | N/A | First release; the spec format is new. Unknown keys are rejected so a future field cannot be silently ignored. |
| 7 | One source of truth | pass | `deploy/mesh.json` generates every SPIRE, Envoy and Kubernetes file; `ztmesh check` (in tests, CI and `check.sh`) fails on drift. The agent socket path is one constant shared by the agent config, Envoy and the manifests. |
| 8 | Small changes, no secrets, validate input | pass | No keys or tokens are committed; keys exist only in temp directories during a run, written owner-only. The spec is size-bounded (1 MiB), strictly typed, and every cross reference is checked; SPIFFE IDs follow the spec; values quoted into HCL are refused if they contain quotes, backslashes, `$` or newlines. |
| 9 | Tests that can actually fail | pass | Empty, invalid and failure paths are covered (no-SAN and multi-SAN certificates, expired, rogue CA, missing files, bad JSON). 12 of 12 hand mutations killed, none survived. |
| 10 | Re-verify | pass | `.tmp/check.sh` run twice, both `CHECK PASS`; `audit_repo.py` OK. |
